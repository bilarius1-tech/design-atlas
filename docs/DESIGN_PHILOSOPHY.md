# DESIGN PHILOSOPHY

## Суть продукта (locked)

См. [ESSENCE.md](ESSENCE.md): Atlas — **библиотека дизайн-систем + dual prompt**, не конструктор сайтов. Сборку делает Cursor или агент Тильды **снаружи**.

## Суть визуала app shell

Design Atlas должен **выглядеть** как продуманный продукт и **вести себя** как инструмент handoff. Красота превью — способ доказать систему до промпта, не декорация.

## Visual first

1. **Типографика ведёт иерархию** — заголовки, подписи, метаданные читаются без «прыжков» веса.
2. **Сетка и ритм** — вертикальный ритм 4/8px; контентная колонка ограничена по `ch` для длинного текста.
3. **Цвет сдержанный** — нейтральная база app shell; акценты из токенов, не произвольные hex в компонентах.
4. **Движение дозированно** — Motion только там, где ориентирует (переход темы, раскрытие); без декоративного шума.
5. **Референсы стилей** — когда появится библиотека, каждый стиль демонстрируется на **реальных** паттернах (карточка, заголовок, кнопка), не на абстрактных градиентных плашках.

## Agent ready

- Визуальные решения **дублируются** структурой: токены, имена, контракты.
- Промпты и экспорт строятся из **полей схемы**, не из свободного описания «сделай красиво».
- Документация для агентов непротиворечива коду.

## Anti patterns (No AI slop)

| Нельзя | Вместо этого |
|--------|----------------|
| «В современном мире дизайна…» | Конкретный факт, дата, источник |
| Синонимическая вода | Одно точное предложение |
| Универсальные hero с stock-иллюстрацией | Системная типографика + реальный preview стиля |
| 12 одинаковых card grid без иерархии | Разметка по типу контента |
| Случайные радиусы и тени | Токены `radius.*`, `shadow.*` |

Ревью: [templates/CONTENT-REVIEW.md](templates/CONTENT-REVIEW.md), [templates/STYLE-REVIEW.md](templates/STYLE-REVIEW.md).

## App shell vs style library

| | App shell | Style library entry |
|---|-----------|---------------------|
| Цель | Навигация, доверие, читаемость | Демонстрация конкретного направления |
| Токены | `design/system/` | `design/styles/<id>/` |
| Менять часто | Редко | При кураторстве стиля |

Сначала доводим shell до эталона, затем добавляем стили — см. [ROADMAP.md](ROADMAP.md) P1→P3.

## Доступность как часть эстетики

Контраст, focus, размер кликабельных зон — не «добавим потом». См. [ACCESSIBILITY.md](ACCESSIBILITY.md).

## Решения по умолчанию (пока нет Figma-единого источника)

- Шрифт UI: системный стек + один выразительный display для заголовков (уточняется в DESIGN_SYSTEM).
- Lucide для иконок; размеры из токенов `icon.sm | md | lg`.
- Radix — когда нужен keyboard model (dialog, menu).

Изменения дефолтов — через DESIGN_SYSTEM + при необходимости ADR-0004.
