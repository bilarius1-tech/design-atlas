# Часть V. План реализации PHASE 0–12

## Перед стартом

1. Новый GitHub-репозиторий.
2. Старый dizain-prompty сохранить отдельно.
3. Изучить наработки, не копировать архитектуру.
4. Отобрать контент с проверкой происхождения.
5. Строить по этому ТЗ.

## PHASE 0 · Repository Bootstrap

Next.js, TS strict, Tailwind, ESLint, Prettier, pnpm, Git, env, структура, README, CI.  
Приёмка: `pnpm install|dev|lint|typecheck|test|build`.

## PHASE 1 · Project Harness

AGENTS.md, Cursor Rules, docs, ADR, Skills, шаблоны задач/отчётов, Git workflow, CI gates. Skills — рабочие инструкции, не пустышки.

## PHASE 2 · Core Design System

Нейтральная редакционная оболочка самого DESIGN ATLAS (не один из каталожных стилей).

## PHASE 3 · Content Engine

Zod-схемы, типы, registry, валидатор, loader, тестовый стиль-данные.

## PHASE 4 · Visual Playground

Универсальный renderer групп компонентов по токенам стиля.

## PHASE 5 · Demo Landing Engine

Блочный движок лендингов с вариантами композиций; не форсировать одинаковый лендинг.

## PHASE 6 · Reference Style

Полный Swiss International Style до аудита. Не расширять каталог до приёмки эталона.

## PHASE 7 · Prompt & Export Engine

Просмотр/копирование/скачивание MD + ZIP из единого источника данных.

## PHASE 8 · Main Application

Главная, каталог, страница стиля, компоненты, глоссарий, about, фильтры, поиск.

## PHASE 9 · Localization RU/EN

Профессиональная адаптация EN, не сырой машинный перевод. ID/токены не переводить.

## PHASE 10 · QA & Visual Review

Critical/Major до релиза обязательны.

## PHASE 11 · Content Expansion

Группы по 3–5 стилей. Цель ~30 полноценных, не поверхностных.

## PHASE 12 · Production Release

Домен, HTTPS, SEO, мониторинг, бэкап репо, production-ready.

## Правило перехода

Следующая фаза только после приёмки предыдущей, обновления docs, отсутствия critical, рабочих команд, тестов и соблюдения контрактов.
