# Часть II. Техническая архитектура

## 1. Стратегия

Монолитное приложение с модульной архитектурой. Без микросервисов на старте.

Цели:

- быстрый интерфейс и SEO;
- расширяемость каталога;
- независимость контента от кода;
- добавление стилей без переписывания приложения;
- предсказуемая генерация файлов;
- работа без обязательного AI API;
- путь к админ-панели позже.

## 2. Стек

**Frontend:** Next.js App Router, React, TypeScript strict, Tailwind CSS v4, CSS Variables, Radix UI по необходимости, Lucide, Motion только для оправданных анимаций.

Не ставить UI-kit целиком и не превращать продукт в стандартный shadcn-интерфейс. shadcn допустим как источник отдельных примитивов.

**Backend (v1):** Server Components, Route Handlers, Server Actions по необходимости, Zod.

**Контент:** JSON + MDX + Markdown + TypeScript schemas. Каталог в Git, без БД в первой версии.

**Позже:** PostgreSQL, Drizzle, admin, черновики/публикации/версии/переводы.

**Тесты:** Vitest, Playwright, axe-core, TypeScript, ESLint.

**Инструменты:** GitHub, Cursor, GitHub Actions, pnpm, Node.js LTS, Docker при необходимости. Версии фиксируются lock-файлом.

## 3. Принцип разделения

Не смешивать:

1. Данные стиля  
2. Логику визуализации  
3. Контент demo landing  
4. Генерацию инструкций  
5. Компоненты приложения  

Данные не содержат React-код. Произвольный JSX из JSON/Markdown не исполняется. Демо используют контролируемый набор компонентов и проверенные данные.

## 4. Рендеринг стилей

`Style Definition → Validator → Style Renderer → Demo Components → Preview`

Стиль передаёт токены, типографику, геометрию, настройки компонентов, контент демо и метаданные. Уникальные композиции допускаются только с явной причиной.

## 5. Производительность

Server Components по умолчанию; Client Components только для интерактивности; lazy loading тяжёлых демо; оптимизация изображений; локальные шрифты с лицензиями; минимум JS на каталоге; не грузить все демо сразу.

## 6. Локализация

RU — основной, EN — дополнительный. Идентификаторы стабильны и независимы от языка:

```text
style.id = "swiss-international"
style.title.ru = "Швейцарский интернациональный стиль"
style.title.en = "Swiss International Style"
```

## 7. Масштабирование (архитектурные требования, не scope v1)

Новые стили/компоненты, коллекции, сравнение, пользовательские подборки, разные наборы экспорта, новые языки, история изменений дизайн-систем.
